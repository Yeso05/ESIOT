1. Introduction and objectives


Headless operation means running a computer without a local display or input devices. A Raspberry Pi is a credit-card-sized Linux computer; configuring it headless lets you deploy it in a robot, sensor node, server rack, or enclosure where no screen exists.


Operating principle


The first-boot configuration (hostname, user, Wi-Fi credentials, SSH) is written to the microSD card before the Pi is powered. On boot, the Pi joins the network, obtains an IP address by DHCP, advertises its hostname by mDNS, and starts the SSH daemon. You then open a secure shell from another computer on the same network.


Why it matters


Headless Pis are the standard for IoT gateways, edge AI, home servers, data loggers, and lab automation. Remote administration is a core skill for embedded and hardware-validation roles.


Prerequisites


  • Basic networking: IP address, subnet mask, gateway, DHCP, DNS.
  • Linux command line basics.
  • Client-server idea and public-key cryptography (conceptual).

3. Step-by-step procedure


Step 1: Flash and preconfigure


  1. Install Raspberry Pi Imager on your computer.
  2. Choose the Pi model, then Raspberry Pi OS Lite (64-bit) (no desktop, smallest footprint), then your microSD card.
  3. Open Edit Settings (OS customisation): set hostname, username and password, Wi-Fi SSID, password and country, locale and time zone.
  4. On the Services tab, enable SSH (password, or paste your public key).
  5. Write the card, eject it, insert it into the Pi, and power on. First boot takes one to three minutes.


Misconception: older guides tell you to add wpa_supplicant.conf to the boot partition and use the default user pi. Current Raspberry Pi OS (Bookworm onward) uses NetworkManager and has no default user; create the user in Imager. An empty file named ssh on the boot partition still enables SSH.


Step 2: Find the Pi


ping raspberrypi.local        # replace with your hostname
arp -a                        # list devices on your LAN
nmap -sn 192.168.1.0/24       # scan the subnet (if nmap is installed)


You can also read the DHCP client list in your router's admin page.


Step 3: Log in


ssh youruser@raspberrypi.local
# or: ssh youruser@192.168.1.xx


Step 4: Update and configure


sudo apt update && sudo apt full-upgrade -y
sudo raspi-config          # locale, interfaces (I2C, SPI), expand options
sudo reboot


Step 5: Use key-based authentication


# on your computer
ssh-keygen -t ed25519
ssh-copy-id youruser@raspberrypi.local
# on the Pi, after confirming key login works
sudo nano /etc/ssh/sshd_config   # set: PasswordAuthentication no
sudo systemctl restart ssh


Test the key login in a second terminal before disabling passwords, otherwise you can lock yourself out.


Step 6: Give it a stable address


Best: a DHCP reservation on the router (binds the Pi's MAC to one IP). Alternative: a static IP with NetworkManager:


nmcli connection show
sudo nmcli con mod "YOUR_CONNECTION" ipv4.addresses 192.168.1.50/24 \
  ipv4.gateway 192.168.1.1 ipv4.dns 1.1.1.1 ipv4.method manual
sudo nmcli con up "YOUR_CONNECTION"


Choose an address outside the router's DHCP pool to avoid conflicts.


Step 7 (optional): Remote desktop


Use RealVNC, enabled in raspi-config under Interface Options, with the desktop edition of Raspberry Pi OS. Lite has no desktop to share, so stay with SSH for it.


Step 8: Safe shutdown


sudo shutdown -h now   # wait for the green LED to stop, then remove power


Pulling power while the card is writing can corrupt the filesystem.

6. Solved problems


Problem 1 (easy): hosts in a /24

Find: usable hosts. Formula: N = 2(32−n) − 2. Substitute: n = 24, so N = 28 − 2 = 256 − 2 = 254. Interpretation: a home network 192.168.1.0/24 can hold 254 devices, including the router.


Problem 2 (moderate): /26 subnet

A lab uses 192.168.10.0/26. Find the mask and usable hosts. Host bits = 32 − 26 = 6, so N = 26 − 2 = 62. Mask: last octet 11000000 = 192, so 255.255.255.192. Usable range 192.168.10.1 to 192.168.10.62, broadcast 192.168.10.63. Interpretation: a 40-Pi cluster fits, a 70-Pi cluster does not.


Problem 3 (GATE-style): power budget

Ten Raspberry Pi 4 nodes each draw 1.5 A peak at 5 V. One shared supply must have 20% margin. Required current = 10 × 1.5 = 15 A; with margin 1.2 × 15 = 18 A. Power = 5 V × 18 A = 90 W. Shortcut: margin of 20% means multiply by 1.2. Interpretation: choose a 5 V supply rated at 90 W or more, with short thick wiring to limit voltage drop.





7. Interview preparation


Ten practice questions for embedded, hardware validation, and IoT roles. Click to reveal.


1. What does headless mean, and why use it?
Running without display or peripherals. It cuts cost and size, and suits deployed nodes that are managed remotely.


2. How do you enable SSH before first boot?
Use Imager's OS customisation, or place an empty file named ssh on the boot partition. Follow-up: how would you do it on an already running Pi? Use sudo raspi-config or sudo systemctl enable --now ssh.


3. The Pi is not on the network. How do you debug?
Check power LED and supply, then activity LED for boot. Verify Wi-Fi credentials and country, try Ethernet, read the router client list, and as a last resort attach a USB-UART console to read boot messages.


4. "Connection refused" versus "Connection timed out"?
Refused: the host replied and nothing is listening on the port (sshd off, or wrong port). Timed out: packets get no reply, so wrong address, different network, firewall, or the device is down.


5. Why prefer SSH keys over passwords?
Keys resist brute-force and phishing and enable automation. The private key never leaves your machine; the Pi stores only the public key in ~/.ssh/authorized_keys.


6. Static IP or DHCP reservation?
Reservation is usually better: one central place to manage addresses and the Pi still uses standard DHCP. Static on the device risks conflicts if the address is inside the DHCP pool.


7. How does raspberrypi.local work?
Multicast DNS (UDP 5353) via Avahi on the Pi. Clients ask the local network who owns the name. It does not cross routers or VLANs by default.


8. Why can a Pi reboot randomly under load?
Under-voltage from a poor supply or cable (voltage drop = I × R). Check vcgencmd get_throttled and use a rated supply.


9. How do you protect an SD card in a field deployment?
Clean shutdown, quality card, reduce writes (logs to RAM or external storage), read-only root or overlay filesystem, UPS or supercap for power loss, backups of the image.


10. How would you provision 50 identical Pis?
Build and test one golden image, flash copies with Imager or scripts, set unique hostnames, manage configuration with Ansible or cloud-init-style first-boot scripts, and track MAC addresses and IPs in a spreadsheet or inventory.


Industry view: the same skills (remote bring-up, serial console, reproducible images, secure access) apply to embedded Linux boards, test fixtures, and edge devices in product validation labs.





8. Applications and industry relevance


  • IoT gateways and data loggers: collect sensor data over I2C/SPI and push it to a cloud service.
  • Edge computing: camera analytics, local inference.
  • Home and lab servers: network-wide ad blocking (DNS), media, Home Assistant.
  • Test automation: Pis driving GPIO relays in hardware-in-the-loop rigs.
  • Robotics and kiosks: controllers in enclosures with no screen.


Advantages: low cost, low power, remote management. Limitations: SD card wear, limited compute, power sensitivity, Wi-Fi reliability. Common challenges: finding the device on corporate networks, client isolation on guest Wi-Fi, and key management across many devices. Roles: embedded engineer, IoT developer, validation and test engineer, DevOps for edge.
